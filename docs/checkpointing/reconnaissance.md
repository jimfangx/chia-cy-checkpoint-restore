## Compiler entry and actual order

[sims/firesim/sim/midas/src/main/scala/midas/stage/GoldenGateStage.scala](../../sims/firesim/sim/midas/src/main/scala/midas/stage/GoldenGateStage.scala) defines `GoldenGateMain` and phases GetIncludes → Checks → AddDerivedAnnotations → CreateParametersInstancePhase → FIRRTL defaults/checks/AddCircuit → GoldenGateCompilerPhase. The Chisel entry is [sims/firesim/sim/midas/src/main/scala/midas/chiselstage/Generator.scala](../../sims/firesim/sim/midas/src/main/scala/midas/chiselstage/Generator.scala); invocation recipes are [sims/firesim/sim/make/goldengate.mk](../../sims/firesim/sim/make/goldengate.mk).

[sims/firesim/sim/midas/src/main/scala/midas/stage/GoldenGateCompilerPhase.scala](../../sims/firesim/sim/midas/src/main/scala/midas/stage/GoldenGateCompilerPhase.scala) constructs these separate compilers:

1. `targetLoweringCompiler`: RunConvertAssertsEarly, ConvertAsserts, InferReadWrite, SimplifyMems, `Forms.LowForm`, configured `TargetTransforms`. These are requested dependencies, not a claim that FIRRTL executes every pass in textual list order. The dependency manager's printed `Pre-GG Target Transformation Ordering` is authoritative for a specific configuration.
2. `loweredTarget` → compiler with LowForm, InferReadWrite, MidasTransforms. This is the proposed explicit StateID hook boundary.
3. Host lowering requests AutoILATransform, HostClockWiring, LowForm, configured HostTransforms.
4. FPGA backend requests SeparateWriteClocks, SetDefaultReadUnderWrite, SimplifyMems and LowForm.
5. Separate WriteXDCFile/SystemVerilogEmitter compiler, returning annotations.

**Source caveat:** `loweringCompiler.execute(simulator)` has its return value discarded; `fpgaBackendCompiler.execute(simulator)` uses the earlier state. Do not assume host-transform circuit edits reach emitted RTL. This reconnaissance does not fix that behavior.

[sims/firesim/sim/midas/src/main/scala/midas/passes/MidasTransforms.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/MidasTransforms.scala) explicitly folds `runTransform` over the following sequence (ResolveAndCheck, intermediate FIRRTL/annotation emissions and repeated high/middle/low lowering occur between the named groups):

- ConvertExternalToInternalAnnotations; ResolveAndCheck; HoistStopAndPrintfEnables; RemoveValidIf; ConstantPropagation; SplitExpressions; ResolveKinds; CommonSubexpressionElimination; DeadCodeElimination; InferResets; CheckTypes; high-to-middle and middle-to-low lowering.
- Optional FireAxe NoC partition, remove or extract passes; emitted pre/post-partition IR. These change hierarchy and boundaries and are excluded from the initial checkpoint support set.
- PlusArgsWiringTransform; CoerceAsyncToSyncReset; EnsureNoTargetIO; BridgeExtraction; lowering; AutoCounterTransform; AssertionSynthesis; PrintSynthesis; TriggerWiring; GlobalResetConditionWiring.
- ChannelClockInfoAnalysis; UpdateBridgeClockInfo; WrapTop; LabelMultiThreadedInstances; optional LabelSRAMModels when GenerateMultiCycleRamModels is enabled.
- ExtractModel; lowering; EnableAndRunDedupOnce except partition/remove; PromotePassthroughConnections; FAMEDefaults; FindDefaultClocks; ChannelExcision; InferModelPorts.
- FAMETransform; DefineAbstractClockGate; AddRemainingFanoutAnnotations; MultiThreadFAME5Models; InlineInstances; ResolveKinds; EmitAndWrapRAMModels; SimulationMapping; xilinx.HostSpecialization; ResolveAndCheck.

Thus “immediately before FAMETransform” is already too late to define original DUT identity: optimization, reset coercion, extraction, deduplication and optional RAM modeling have happened.

## Viable semantic StateID boundary and register trace

Insert an opt-in discovery invocation on `loweredTarget`, before feeding it into the simulator compiler in GoldenGateCompilerPhase. Save the same lowered circuit as the clean replay reference. Widths and memory shapes are resolved; no Golden Gate instrumentation, bridge extraction, FAME channels or model replacement has yet been introduced. Select the DUT instance explicitly; exclude harness/bridge implementation state by selection, not name heuristics.

This boundary defines **pre-Golden-Gate lowered RTL** state. Target lowering may already simplify memories or remove/reshape source objects. If the contract requires identity of every original Chisel object, seed provenance before lowering and explicitly map aggregates, deleted/constant objects and memory-port state into this boundary. Do not advertise the lowered inventory as a lossless inventory of all elaborated source names.

A concrete source trace is `GCDDUT.inner1.x` in [sims/firesim/sim/src/main/scala/midasexamples/GCD.scala](../../sims/firesim/sim/src/main/scala/midasexamples/GCD.scala): `GCDInner.x` is a register loaded from `io.a`, otherwise conditionally subtracted; `inner1` and `inner2` are separately annotated FAME models. `x` has an inferred 16-bit data path. Preserve two instance-qualified semantic identities even though both instances use the same module definition.

- At the proposed boundary enumerate each instance's DefRegister/DefMemory and original clock/reset/init expressions. Use deterministic canonical instance path + object + kind/shape ordering, with a build-bound manifest. IDs must not depend on traversal hash-map order, host allocation, or physical placement.
- WrapTop creates the FAMETop wrapper and a RenameMap in [sims/firesim/sim/midas/src/main/scala/midas/passes/fame/WrapTop.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/fame/WrapTop.scala). ExtractModel recursively invokes PromoteSubmodule in [sims/firesim/sim/midas/src/main/scala/midas/passes/fame/ExtractModel.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/fame/ExtractModel.scala), moving annotated `inner1`/`inner2` models toward the top. Track instance paths through those transformations, not merely the register's local name.
- Dedup may share module definitions; it must not collapse per-instance StateIDs. Renamable FIRRTL target annotations are useful, but arbitrary custom transforms must be audited for complete rename maps.
- [sims/firesim/sim/midas/src/main/scala/midas/passes/fame/FAMETransform.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/fame/FAMETransform.scala) `FAMEModuleTransformer`, `onExpr`/`onStmt` rewrite clock and port references recursively; ordinary `x` remains target sequential storage in the FAME1 path, clocked by the substituted gated target clock. `hostFlagReg`, clock enable registers and channel `firedReg`s are newly generated simulator state, not semantic `x`. `finishing` combines input validity/output completion with clock-token validity; it is not one host tick per target cycle.
- SimulationMapping links the transformed target into generated SimWrapper/FPGATop/platform RTL. [sims/firesim/sim/midas/src/main/scala/midas/passes/SimulationMapping.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/SimulationMapping.scala) also emits `.const.h`, `.const.vh`, partition and peer-address collateral. Preserve a separate final implementation locator map through this linking/emission; never derive stable IDs from final Verilog names alone.

This is a source trace, not an observed generated-netlist trace: no GCD elaboration or StateID propagation test ran in M0. M1 must test that both GCD instances retain separate IDs and fail on lost/ambiguous mappings. Protection against DCE alone is insufficient to preserve memory contents and provenance.

Memory hazards: [sims/firesim/sim/midas/src/main/scala/midas/passes/fame/LabelSRAMModels.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/fame/LabelSRAMModels.scala) turns annotated DefMemory objects into modules; [sims/firesim/sim/midas/src/main/scala/midas/passes/fame/EmitAndWrapRAMModels.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/fame/EmitAndWrapRAMModels.scala) replaces annotated module bodies with AsyncMemChiselModel wrappers, derives depth from address width and rejects read/write ports via `require(readWritePorts.isEmpty)`. [sims/firesim/sim/midas/src/main/scala/midas/models/sram/AsyncMemModel.scala](../../sims/firesim/sim/midas/src/main/scala/midas/models/sram/AsyncMemModel.scala) and [sims/firesim/sim/midas/src/main/scala/midas/models/sram/RegfileModel.scala](../../sims/firesim/sim/midas/src/main/scala/midas/models/sram/RegfileModel.scala) own modeled storage and command/response behavior. [sims/firesim/sim/midas/src/main/scala/midas/passes/fame/MultiThreadFAME5Models.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/fame/MultiThreadFAME5Models.scala) introduces thread indexing and explicitly contains `TODO: Renames!`. Reject these optional paths initially unless a tested logical-address/thread mapping is supplied. Capture memory read latency/pending outputs as well as array contents; adding a read port blindly can change inference and behavior.

## Bridge and DMA integration

[sims/firesim/sim/midas/src/main/scala/midas/passes/ExtractBridges.scala](../../sims/firesim/sim/midas/src/main/scala/midas/passes/ExtractBridges.scala) lifts bridge boundaries; [sims/firesim/sim/midas/src/main/scala/midas/widgets/Bridge.scala](../../sims/firesim/sim/midas/src/main/scala/midas/widgets/Bridge.scala) and [sims/firesim/sim/midas/src/main/scala/midas/widgets/BridgeAnnotations.scala](../../sims/firesim/sim/midas/src/main/scala/midas/widgets/BridgeAnnotations.scala) connect target annotations to host BridgeModule elaboration. [sims/firesim/sim/midas/src/main/scala/midas/core/SimWrapper.scala](../../sims/firesim/sim/midas/src/main/scala/midas/core/SimWrapper.scala) constructs channel plumbing; [sims/firesim/sim/midas/src/main/scala/midas/core/FPGATop.scala](../../sims/firesim/sim/midas/src/main/scala/midas/core/FPGATop.scala) elaborates bridge, stream and host-memory interconnects.

A future CheckpointBridge can use Widget MMIO controls and `StreamToHostCPU` / `StreamFromHostCPU` from UsesBridgeStreams: logical payload is **512 bits**, one stream per direction per bridge per documented interface. On the host `streaming_bridge_driver_t` exposes `pull`, `push`, `pull_flush`, and 64-byte stream width. [sims/firesim/sim/midas/src/main/cc/core/stream_engine.h](../../sims/firesim/sim/midas/src/main/cc/core/stream_engine.h) abstracts the engine. Neither API reads internal DUT state: banked capture/restore access, freeze control and an inventory are new work. Keep that hardware synthesizable and validate via metasim before any hardware claim.

A clock counter reaching C, PeekPoke DONE, or stopping one bridge is not a global checkpoint cut. Stop issuance of new target events, establish a coherent phase across clock tokens/models, freeze or serialize target-facing channels and bridge state, then settle/capture physical host transactions, software drivers and memory consistently. Outstanding *target* transactions should remain live in the snapshot; do not force the DUT pipeline idle. Treat host-clock counters separately from target cycles. Exactly-once handling of external effects (disk writes, UART output, network traffic) requires a journal/replay policy.

## Papers and unsupported-state policy

Both root PDFs were read using temporary pypdf extraction (pdftotext is absent). Strober, `3007787.3001151.pdf`, pp. 5–6, describes scan extraction and formal matching into gate-level replay; pp. 6–7 discuss retiming and extra history/I/O rather than a trivial register-name map. DESSERT, `DESSERT_Debugging_RTL_Effectively_with_State_Snapshotting_for_Error_Replays_across_Trillions_of_Cycles.pdf`, section III, requires RTL state plus input/output trace over the replay window; section V describes ganged simulation. Their historical scan machinery does not establish support in this checkout. Use banked access per the current plan.

Initial implementation must explicitly reject: opaque sequential ExtModules/blackboxes without adapters; unsupported clocks/resets (including async-reset semantics that coercion changes); unresolved widths; unsupported memory latency/read-under-write/masks or macro organization; incomplete rename/deletion maps; FAME5 threading and optional RAM replacement without adapters; FireAxe/multi-FPGA state; unregistered drivers or nonreplayable external inputs; incomplete transport cuts; unknown/X state without a defined encoding and policy. These are proposed fail-closed requirements, not existing checkpoint checks.

Keep `.rtlckpt` semantic state and `.fsckpt` implementation/runtime state independently usable and independently versioned. Finite standalone Level-2 replay needs the boundary trace; unlimited continuation needs an authoritative live environment or complete deterministic input source. Bind snapshots to circuit/configuration/manifest/build hashes, clock phase and cycle; never silently drop state or translate FASED into another timing model.
